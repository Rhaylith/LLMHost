Help: what the parameters mean

  
  


  
Sampling (the Parameters panel in Chat)

  

    
Temperature 0 – 2

      
How adventurous the next word choice is. Low = focused and repeatable, high = varied and creative.
        
0.0–0.3 for code, extraction and facts · 0.7 for normal chat · 1.0+ for brainstorming or stories.

    
Top P 0 – 1

      
Only the most likely words whose probabilities add up to P are considered. Lower = safer, more predictable.
        
0.95 is a good default. 0.5 gives very conservative text. Change either Temperature or Top P, not both.

    
Top K

      
Consider only the K most likely words at every step. 0 disables it.
        
40 (default). 1 = always the single most likely word (deterministic, "greedy").

    
Min P 0 – 1

      
Drops words that are less than P × (the best word's probability). A modern, gentler alternative to Top K / Top P.
        
0.05 (default). 0.1 for tighter output at high temperatures.

    
Repeat / Frequency / Presence penalty

      
Discourage repeating words. Repeat (1.0 = off, 1.1 default) punishes anything seen recently; Frequency grows with each repetition;
        Presence is a flat cost for any word already used. Negative frequency/presence values encourage repetition.
        
If a small model loops ("the the the…"), raise Repeat penalty to 1.15 or Frequency penalty to 0.3.

    
Max tokens

      
Upper limit on the length of the answer. −1 = until the model stops or the context is full. One token ≈ ¾ of an English word.
        
200 for short answers · 2000 for essays. The finish reason is length when the limit cut the answer.

    
Seed

      
Fixes the random choices so the same prompt gives the same answer (with the same model and settings). Blank = random.
        
Seed 42 + Temperature 0.7 → reproducible variations. Temperature 0 is always deterministic.

    
Stop strings

      
Generation ends as soon as one of these appears (it is not included in the output). Comma separated; \n means a line break.
        
###, \n\n — stop at a "###" marker or at the first blank line.

    
System prompt

      
Standing instructions that apply to the whole conversation: role, tone, rules, format.
        
"You are a concise assistant. Answer in at most three sentences and reply in German."

    
JSON mode / JSON schema

      
Forces the output to be valid JSON, or to match a JSON Schema exactly (enforced by a grammar while generating, so it cannot be malformed).
        
{"type":"object","properties":{"city":{"type":"string"},"temp_c":{"type":"number"}},"required":["city","temp_c"]}

    
Prompt cache

      
Keeps the already-processed start of the conversation in memory, so a follow-up message only processes the new text. Leave on; turn off to measure raw speed.
        
The "N prompt tokens cached" note under a reply shows how much was reused.

    
Reasoning

      
For "thinking" models (Qwen3, DeepSeek-R1, gpt-oss…): off skips the thinking phase (fast), low / medium cap how long it may think
        (≈500 / ≈2000 tokens), high / on let it think freely. Thinking is shown in its own grey block and is not sent back to the model.
        
Quick factual questions: off. Maths or planning: high.

    
Use MCP tools

      
Gives the model the tools of the MCP servers in Server & Settings → MCP servers. With "Ask before each tool call" you approve every call (Allow once / Always allow this tool / Deny).
        
Ask "What files are in my project folder?" with a filesystem MCP server connected.

  


  
Loading a model (Load dialog, ⚙ defaults dialog, load in the CLI)

  

    
Device and GPU layers

      
CPU uses only the processor. GPU all puts every layer in graphics memory (fastest). GPU auto offloads as many layers as fit. "GPU layers" sets an exact count (overrides Device).
        
CLI: load qwen3 --gpu max · --gpu auto · --gpu 0.5 (half of the layers) · --gpu-layers 20.

    
Context length

      
How many tokens (prompt + conversation + answer) the model can keep in view. Bigger = longer conversations, but more memory (KV cache).
        
4096 for chat · 16384+ for long documents. The "Will it fit?" box shows the memory cost live.

    
Batch size

      
How many prompt tokens are processed at once. Larger = faster prompt processing, slightly more memory.

    
CPU threads

      
Threads used for the CPU part of generation. 0 = automatic (75% of the cores). On many-core CPUs, fewer threads can be faster.

    
K / V cache type, Flash attention

      
The KV cache stores the conversation state. q8_0 halves its memory, q4_0 quarters it, with a small quality cost. A quantized V cache needs Flash attention (switched on automatically).
        
Long context on a small GPU: K = q8_0, V = q8_0, Flash attention on.

    
mmap / mlock

      
mmap maps the model file instead of copying it (fast start, low load RAM). mlock pins it in RAM so it is never swapped out.

    
Max concurrent predictions

      
How many requests the model generates at the same time (continuous batching). Others wait in a queue. 1 = strictly one at a time.
        
4 lets several API clients share one loaded model.

    
Idle TTL

      
Unloads the model after this many idle minutes to free memory. 0 = keep loaded. It loads again on the next request.

    
Identifier

      
The name used for this model in the API ("model": "…"). Default: the file name.

    
Vision (mmproj)

      
Loads the multimodal projector that sits next to a vision model so it can read images (attach with 📎, paste or drop). Costs a little extra memory.

    
GPUs, priority and split

      
Tick the GPUs to use; the order is the priority. The model stays on the first GPU if it fits and spills to the next ones otherwise.
        Ratios override that. Split mode: layer (default), row, or single GPU.
        
CLI: load big-model --gpus 0,1 --split 3,1 — three quarters on GPU 0, one quarter on GPU 1.

    
"Will it fit?" and the guardrail

      
Before loading, the app adds weights + KV cache + compute buffers and compares with free memory. Guardrail (Settings): off never refuses,
        balanced refuses loads that cannot fit, strict also refuses tight ones. "Load anyway" skips the check.
        
CLI: fit qwen3-30b --ctx 32768 --gpu prints the estimate without loading.

    
Per-model defaults (⚙)

      
Saves the load settings and the inference settings (temperature, system prompt…) for one model. They apply automatically in the UI, the API and the CLI whenever that model is loaded or requested.

  


  
Server & Settings

  

    
Bind host and port

      
127.0.0.1 = only this computer. 0.0.0.0 = every device on your network. Default port 1234. Takes effect after a restart.

    
API tokens

      
With "Require an API token" on, every /v1 and /api request needs Authorization: Bearer <token>. Each token has permissions:
        chat, embeddings, models:read, models:manage (load/unload/download), app (chats, presets, logs), admin (everything). The secret is shown once when created.
        
curl http://localhost:1234/v1/models -H "Authorization: Bearer ait_…"

    
Runtimes and backend

      
Which llama.cpp build runs the models: Vulkan (GPU) or CPU builds with AVX/AVX2/AVX-512. "Automatic" picks the best for this machine. A change applies after a restart (Ctrl+Shift+R opens this panel).

    
Downloads

      
Downloads are queued, resumable and SHA-256 verified. "Max concurrent downloads" limits parallel transfers. A Hugging Face token is only needed for gated models.
        
Paste user/model:Q4_K_M, a huggingface.co link or a direct .gguf URL into Discover.

    
MCP servers (mcp.json)

      
Local servers start a process; remote ones use a URL.
        
{"mcpServers": {"files": {"command": "npx", "args": ["-y","@modelcontextprotocol/server-filesystem","D:/docs"]}, "web": {"url": "https://example.com/mcp", "headers": {"Authorization": "Bearer …"}}}}

  


  
Chat features

  

    
Edit, regenerate, variants

      
Hover a message: ✎ edits it (a user message is resubmitted as a new variant), ↻ regenerates an answer (the old one stays as a variant), 🗑 deletes it and what follows.
        Use ‹ 2/3 › to switch between variants.

    
Documents

      
Attach .pdf, .docx, .txt or .md with 📎. If the text fits the context it is given whole; otherwise only the passages that match your question are used and shown under "Sources" with [n] citations.
        Loading an embedding model improves the matching.

  


  
Using the API

  


  
Command line

  
llmhost                                   open the app window (second launch just brings it back)
llmhost get                               interactive search → pick a model → pick a quantization
llmhost get user/model:Q4_K_M             download directly (also links and .gguf URLs)
llmhost ls --json     |  ps --json        list models / loaded models
llmhost load qwen3 --gpu max --ctx 8192 --parallel 4 --identifier my-qwen
llmhost fit qwen3 --ctx 32768             memory estimate before loading
llmhost chat qwen3                        terminal chat (or --server http://host:1234)
llmhost server start | status | stop      background server (daemon); also: daemon up|down|update|install
llmhost token create laptop --perm chat,models:read
llmhost mcp list | tools | call demo add {"a":1,"b":2}
llmhost runtime list | select bundled:vulkan
llmhost log stream                        follow the server log
Inside the shell: /help lists everything, /set temperature 0.3, /params shows the current values.
